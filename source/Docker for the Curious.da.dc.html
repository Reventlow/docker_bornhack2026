## begreber

Hvorfor containere findes

“Men det virker
på min maskine…”
— enhver udvikler, lige før en deadline
>

En app er aldrig bare kode. Den slæber en runtime, biblioteker, konfigurationsfiler og særheder fra den maskine, den voksede op på, med sig.

>

Flyt den et andet sted hen, og noget mangler, er i den forkerte version eller ligger det forkerte sted.

>

En container pakker appen sammen med alt, den har brug for — én forseglet enhed, der kører ens på enhver maskine.

## begreber

Hvad en container er

En helt almindelig proces på din maskine — der kører i sin egen lille forseglede verden.

isoleret

Sit eget filsystem, netværk og sin egen procesliste. Den kan ikke se resten af din maskine.

letvægt

Den deler din kerne — ingen falsk hardware, intet ekstra OS. Starter på millisekunder.

flytbar

Det samme image kører identisk på enhver maskine med Docker — laptop, server, cloud.

## begreber

Image vs. container

image — tegningen
skrivebeskyttet skabelon
bygget i lag, delt og cachet
versioneret med tags — nginx:1.27
ændrer sig aldrig, mens containere kører
container — den kørende kopi
en levende instans af et image
lægger et tyndt skrivbart lag ovenpå
start, stop og slet frit
kør mange fra det samme image
image: docker-workshop
→
container: camp
container: camp2
container: test

## reference — tast med

Grundrutinen

Kør hver af dem nu. Læg mærke til, hvad der ændrer sig.

docker ps hvad kører lige nu
docker ps -a …inklusive de stoppede
docker logs camp alt, den har skrevet — genindlæs siden, kig igen
docker stop camp sæt den på pause — og så docker start camp
docker rm -f camp slet den, også mens den kører
docker images images, der ligger på din disk

## den mentale model

Flygtig med vilje

uforanderlige images

Kørende containere ændrer aldrig imaget. Vil du have imaget anderledes? Byg det igen.

engangscontainere

Kvæg, ikke kæledyr. Slet og genskab uden frygt — en frisk er altid én kommando væk.

data bor udenfor

Alt, der er værd at gemme, bliver på din maskine og monteres ind. Det hedder et volume — næste opgave.

$ docker for de nysgerrigedocker workshop
OPGAVE 4 hands-on

Det samme, som en fil

camp/compose.yaml
services:
  web:
    image: elohite/docker-workshop
    ports:
      - "8080:80"
you@laptop:~ 
$ mkdir camp && cd camp
$ nano compose.yaml
$ docker compose up -d
$ docker compose down

Den run-kommando var ved at blive lang. Compose skriver den ned i stedet.

>Læsbar, delbar, ligger i git ved siden af din kode.
>up -d starter alt i filen. down stopper og rydder det hele op.
>Filen er dokumentationen for, hvordan det her kører.

Montér et volume

camp/compose.yaml
services:
  web:
    image: elohite/docker-workshop
    ports:
      - "8080:80"
    volumes:
      - ./html:/usr/share/nginx/html
you@laptop:~/camp 
$ mkdir html
$ nano html/index.html   # skriv hvad som helst
$ docker compose up -d
$ docker compose down && docker compose up -d
# genindlæs — din side overlevede
kolon-reglen
./html : /usr/share/nginx/html
din maskine (vært)inde i containeren

Til venstre for kolon: din verden. Til højre: deres. Samme regel, som du allerede brugte med porte — 8080:80.

## demo — bare kig med her (stor download)

To services, én fil

wordpress/compose.yaml
services:
  wordpress:
    image: wordpress
    ports:
      - "8081:80"
    environment:
      WORDPRESS_DB_HOST: db
      WORDPRESS_DB_USER: wp
      WORDPRESS_DB_PASSWORD: secret
      WORDPRESS_DB_NAME: wordpress
  db:
    image: mysql
    environment:
      MYSQL_DATABASE: wordpress
      MYSQL_USER: wp
      MYSQL_PASSWORD: secret
      MYSQL_RANDOM_ROOT_PASSWORD: "1"
>

To containere, én fil, én docker compose up -d.

>

Compose giver dem et privat netværk. Hver service kan nås ved navn — WordPress finder sin database på db.

>

Et helt CMS med database på localhost:8081 — intet installeret på maskinen.
